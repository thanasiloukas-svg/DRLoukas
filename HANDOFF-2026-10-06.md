to the site. Everything it does to the site runs through one channel:

**Novamira MCP → `novamira/execute-php`** — arbitrary PHP executed on the live server as
WP user ID 1. That is the write path for content, options, files, images and API calls.

Key asymmetry worth understanding:

| | My session | The site's server |
|---|---|---|
| Reach drloukas.com | **blocked** (proxy 403) | n/a (it *is* the site) |
| Reach google.com / GSC / GBP APIs | **blocked** | **open** |
| Reach Google Drive, Instagram, Mogo | **blocked** | **open** |

## 3. GOOGLE SEARCH CONSOLE — full capabilities

### The mechanism
An on-server PHP bridge, built Aug 30, credentialed Sep 3:

```

wp-content/loukas-google/credentials.php  → service account (no secrets in chat, ever)
wp-content/loukas-google/.htaccess        → denies .json/.b64/.key/.pem/.txt (verified 403)
```

Service account `gsc-reader@numeric-anthem-506400-v4.iam.gserviceaccount.com`, Cloud project
`numeric-anthem-506400-v4` (project number 351609807361). It signs its own JWTs with
openssl, caches the token in a transient for 50 minutes.

Usage from any session with Novamira:
```php
require_once WP_CONTENT_DIR.'/loukas-google/google-api.php';
Loukas_Google_API::gsc_sites();
Loukas_Google_API::gsc_query($start, $end, $dimensions, $rowLimit, $filters);
Loukas_Google_API::gsc_inspect($url);
Loukas_Google_API::gsc_sitemaps();
Loukas_Google_API::request($url, $scope, $payload, $method);  // generic
```

### What it can do
- **Both properties visible as `siteFullUser`:** `https://www.drloukas.com/` and `sc-domain:drloukas.com`
- **Search Analytics** — any date range, dimensions query / page / date / device / country,
  up to 25,000 rows, with `dimensionFilterGroups`
- **URL Inspection API** — index verdict, canonical, crawl date, richResults, videoIndexingResult.
  ~6s per URL, so **batch 4–6 per call** (14 URLs exceeds the 60s MCP timeout)
- **Sitemaps** — submission state, last download, error/warning counts, per-type entry counts
- **Search-type segmentation** — WEB / IMAGE / VIDEO

### What it cannot do
- **No Indexing API for normal pages.** Google's Indexing API only accepts JobPosting and
  BroadcastEvent. You **cannot** programmatically request a recrawl of a service page.
  The real levers are IndexNow (automated here, reaches Bing/Yandex), the sitemap, and the
  owner clicking "Request Indexing" in the GSC UI. Never claim a Google recrawl was requested.
- No GSC *settings* writes (users, verification) — read-only analytics and inspection.

### Method gotchas that have each cost real time
1. **`gsc_query()` already wraps `$filters`.** Pass a FLAT array of filter objects:
   `array(array('dimension'=>'QUERY','operator'=>'equals','expression'=>$q))`.
   Wrapping it yourself returns `'dimension' field is required`.
2. **Filter dimensions must be UPPERCASE** (`QUERY`, `PAGE`). Lowercase fails.
3. **Search type can't go through `gsc_query`.** Call `request()` directly with a top-level
   `type` of WEB/IMAGE/VIDEO. `request()`'s signature is
   `($url, $scope, $payload = null, $method = 'GET')` — **scope is the second argument**.
   Passing `'POST'` there signs a JWT with `aud: POST` and fails.
4. **The query dimension is anonymised.** Query-dim totals do NOT match date-dim totals —
   about two thirds of clicks sit in queries Google will not name. **Always take sitewide
   totals from the date dimension** or you will report a click collapse that never happened.
5. **When clicks are all zero, the page dimension returns rows alphabetically** and `rowLimit`
   truncates. Pull a large limit and sort by impressions yourself.
6. **`wp_remote_get` follows redirects**, so a robots-meta check reads the *destination*.
   Pass `redirection=0` when testing index status. **Resolve every URL this way before
   treating it as a page** — about a third of URLs in GSC reports are 301s, drafts or attachments.
7. Site-wide average position (~24) is diluted by out-of-area impressions (Itasca, Elk Grove,
   Schaumburg, and "chin filler the ridges" alone at 1,614 impressions). **It is not a health
   metric. Always segment to Park Ridge.**

### API syntax landmines (each cost a round trip)
1. **Categories must be written BEFORE services** — a free-form service attaches to a
   category and fails if that category isn't on the location yet.
2. **Multi-word category filters must be quoted:** `filter=displayName="Dental clinic"`.
   Unquoted returns 400. Never hand-write gcids; resolve them via `categories:list`.
3. **`readMask` is required**, and `moreHoursTypes` noise will bury you. Request only what
   you need and parse server-side.
4. `GET /v1/attributes?parent=locations/X` — **do not also set `languageCode`/`regionCode`**
   or it 400s.
5. `PATCH .../attributes?attributeMask=...` needs the **full** name,
   `attributes/url_appointment`, not the bare id. Google's own docs example is wrong here.
6. The stored description contains **hard line breaks** — a `str_replace` on a phrase that
   straddles one silently fails. Collapse whitespace or anchor on a short fragment.
7. **Greek is not available as a GBP language attribute.** The location offers exactly 19
   values and Greek isn't one. It had to go in the description instead.
8. **Performance data: every value reading exactly `15` is `insightsValue.threshold`**, a
   privacy floor, not a count. Only the top handful of search terms carry real numbers.
9. 6 months × 9 metrics is ~304 KB. Write it to a file on the server and parse there.

### The one thing no API exposes: GBP edit history
**Google's own notification emails are the only record.** They name the changed field in the
body. Query that works, via the Gmail connector:
```
from:(businessprofile-noreply@google.com OR google-maps-noreply@google.com)
after:YYYY/MM/DD before:YYYY/MM/DD in:anywhere
```
Re-run this whenever a GBP metric moves without explanation. It is how the call-button
outage below was solved.

## 9. Hard rules for any agent touching this site

- **Never** write `aioseo_options` / `aioseo_options_dynamic` through the MCP option tool —
  it decodes the JSON string into an array and corrupts AIOSEO's storage. Use
  `update_option($name, wp_json_encode($arr))` via execute-php.
- **Never** modify live `.htaccess`. **Never** use `wp_update_option` on `wpassetcleanup_settings`.
- **Never** change existing URL slugs, post titles or H1s.
- **Never** add manual meta / canonical / robots tags — AIOSEO owns those.
- **Never** overwrite an existing `_aioseo_title` / `_description` / `_keyphrases` **unless
  the owner explicitly orders it.**
- **Patient photo consent is settled.** The owner has stated it twice. **Do not ask again.**
  The remaining gate is clinical accuracy. Patient-identifying filenames are never allowed.
- **Vision is for "what treatment does this image show" and nothing else.** It has passed
  4 of 4 AI-generated images as real photographs and once invented an entire image's contents.
  **Treat a vision verdict as a question to put to the dentist, never as a finding to publish
  or to overrule him with.** An AI-provenance header scan ranks **above** the vision check.
- **Two agents must never edit the same page at once** — there is no post locking, and a
  parallel session has already been caught working this site the same day.
- **Do not add `aggregateRating` markup for the practice** — Google excluded self-serving
  reviews in 2019. Earns nothing, risks a manual action.
- **Do not unblock xmlrpc** to silence the Jetpack banner. Blocking it is a security win and
  the only Boost features needing that connection are all switched off.
- **Keep Jetpack Boost.** It is the only page cache and minifier on a host with no OPcache.
- **A 60s MCP timeout does not mean the write failed.** Verify server-side before retrying.
- **The site's signature failure mode, seen four times:** a plugin with every toggle ON and
  no provider, key, quota or stored config — Broken Link Checker billed for 10 months and
  scanned zero links; Image Optimization has never converted a file; `ai/ai.php` has 20+
  features on and zero providers; the embeddings environment has no key.
  **"The toggle is on" proves nothing. Always verify there is a provider and a quota.**
- **Verify a CSS change in the served bundle, not the source file.** Boost combines and
  defers stylesheets into `wp-content/boost-cache/static/<hash>.min.css`, and its `<link>`
  tags use **single quotes** — a `href="..."` regex finds nothing and will mislead you.
- **Sitemaps cache twice.** `?nocache=` only bypasses Boost; AIOSEO caches sitemaps in
  `wp_aioseo_cache`. Clear both before believing a count.
- **Validate JSON-LD with the right regex.** The delivered tag is
  `<script data-jetpack-boost="ignore" type="application/ld+json" class="aioseo-schema">` —
  `type` is not first. Use `#<script[^>]*type="application/ld\+json"[^>]*>(.*?)</script>#s`.
  And validate by `json_decode()`, never by grepping for field names.
